# v5.5 Planning Report — Kiswahili Hymnal

## Source

Brother Kimathi (Kenya) offered a Kiswahili hymnal, translated from English, by email (thread "IN NEED OF UP-TO-DATE HYMNAL SOFTWARE", 2026-09). He sent the file over WhatsApp, and Lemuel saved it as `docs/v5.5/SWAHILI HYMN BOOK .docx` (the space before `.docx` is in the original filename).

Kiswahili is a **new language** for the app, not a correction to an existing one, so this follows the "new language" workflow in `docs/LANGUAGE_PROVISIONING_GUIDE.md`.

## Decisions so far

- **Hymn group code: `SW`**, with IDs `SW1`, `SW2`, … in document order (decided 2026-10-03).
- Questions about the document's content were sent to Kimathi instead of guessed (see below).

## Converting the `.docx` to text

The dev machine has no `pandoc`, `unzip` or `python-docx`, so the text was extracted with plain Python: `zipfile` plus `xml.etree` over `word/document.xml`.

**Gotcha: floating text boxes.** The document has **63 text boxes**. Word stores each one twice: a modern `mc:AlternateContent` choice and a legacy VML `mc:Fallback` copy. A simple regex over `<w:t>` elements therefore:
- **duplicates** every text-box line, and
- **merges** text-box paragraphs into the paragraph that anchors them (e.g. `Sikuabudu pekee yangu1. Nimetekwa...`).

Fix: walk the XML tree, skip everything under `mc:Fallback`, and emit each `w:txbxContent` paragraph as its own line. Treat `w:br` as a newline and `w:tab` as a tab. The result was 3,270 lines of clean text, with no duplicates.

Headers and footers contain only page numbers, so no hymn titles are hidden there.

## What the document contains

About **70 hymns**. Most titles are ALL CAPS, and many include the matching English hymn number, which gives us the `Related: E<n>` link. The number is written inconsistently:

| Example title | Number format |
|---|---|
| `SIKU YA ARUSI-1318` | `-<n>` |
| `UNIVUTE 387` | trailing number |
| `TANGU YESU AINGIE (309)` | in brackets |
| `PANDA ASUBUHI NO.1167`, `TWAKUTANIKA NA BWANA HYMN NO.864` | `NO.` / `HYMN NO.` |
| `UJUMBE NAAMINI E-551`, `IMANI YANGU E-330` | `E-<n>` |
| `I WILL SING THE WONDROUS STORY #331` | `#<n>` |
| `MUNGU NI CHAKULA` / `E.NO 1145` | on the **next line** |
| `MWAMBA WENYE IMARA 1058` / `(ROCK OF AGES)` | English title on the next line |

A script can normalise these, but each `Related:` value should still be checked by hand against the English hymn.

## Problems found

1. **The first hymn has no title.** The document starts with `1. Kanisa la utukufu nasi tu washirika...`.
2. **Some titles aren't in caps**, so a caps-based detector misses them, e.g. `Sikuabudu pekee yangu`, `Wazo la 'kati' la Mungu-972`, `Damu, Neno,Roho na Kanisa`. These hymn boundaries need marking by hand.
3. **Some hymns aren't in Kiswahili.**
   - English: `I Will Sing the Wondrous Story` (#331), `Draw Me Nearer` (#387), `What Can Wash Away My Sin`, `Look Away! O Look Away` (#1206), "In tenderness He sought me", "Thy name is sweet as ointment poured forth".
   - Apparently Kikuyu: `NGIONA UTHERI`, and "Ndina gikeno ndiri na kieha".
4. **One section is badly broken by the text-box layout:** the English Song of Songs hymn "Thy name is sweet as ointment poured forth" (around lines 1560–1720 of the extracted text). It is split into fragments such as `SUS`, `ea-`, `lesis.`, with stanzas out of order.
5. **The layout is inconsistent.** Some stanzas run together on one line, while others are one line per line. Choruses have no label and are separated only by blank lines.
6. **There are probable typos**, e.g. `kalamnu` (karamu?), `niwili` (mwili?), `Halel'uyah sase` (sasa?). These are not safe to fix without a Kiswahili speaker.
7. **Some hymns have no English hymn number**, e.g. `Sikuabudu Pekee Yangu`, `Naangaziwa`, `Hakuna Kitu Kinachoshinda Damu`, `Utukufu kwa Baba`, `Nafsi Yangu Furahia`, `Tumeshinda`, `Nawacha Giza`, `Bwana Yesu Ndiye Njia` (sung to the tune of "Yes, Jesus Loves Me"), `Yesu Mwamba Wetu`, `Watoto wa Mungu`, `Tumeamua`, `Chakutumaini Sina`. This list may not be complete.

# German Hymnal — Source Resync and Pipeline Fixes (Isaiah's team)

- **His question:** what format the TXT file needs to be in.
- **An attachment:** their current file, `Liederbuch_app_v5(typo corr).txt`, saved here as `docs/v5.5/Liederbuch_app_v5(typo corr).txt`.

Lemuel replied the same day. The reply said:
- the format is fine, and strict formatting matters less now that coding agents normalise the lyrics;
- `R` (Russian) references will be dropped, since the app has no Russian hymns;
- the renumbering won't be backward compatible, and the release notes will warn users about it;
- the app is now on Google Play;
- a request for the team's Google accounts, to add them to closed testing.

**Misunderstanding, cleared up the same day.** We read the "(typo corr)" in the filename as a new batch of corrections and replied that they'd be imported. Isaiah replied at 13:29: *"the corrections have actually already been included in the app. I sent it just as a sample of the format we used before, so there's no need to spend time importing it again."* He also said:
- they will prepare a list mapping old hymn numbers to new;
- they've seen the app on Google Play.

They haven't sent Google accounts for closed testing yet.

The import below had already been done by then. **We kept it anyway (Lemuel's decision).** It makes the German script re-runnable, which the renumbered hymnal will need, and the comparison below shows it is safe. Its real value turned out to be finding fixes that exist in the app but are missing from Isaiah's file.

## What the file is

It is the team's master copy of the main German hymnal, **G1–G460**, in the same format as our `german/New_German_hymns.txt`. Ignoring line endings and trailing whitespace, it differs from ours by 15 lines of typo, punctuation and capitalisation fixes.

As Isaiah said, almost all of those fixes were already in the app, because they had been applied directly to `hymns.sql` earlier. Our `.txt` had just never been updated. Only **G64** and **G269** (two punctuation fixes) were new to the app.

## Pipeline changes

- **`ProvisionGermanV2.groovy`:**
  - It was only pointing at `GermanNewHymn_2019Dec.txt` (G1001–G1020), with no delete step, so it couldn't be re-run at all. It now deletes G1–G1336 and provisions both `New_German_hymns.txt` (G1–G460) and `GermanNewHymn_2019Dec.txt` (G1001–G1020).
  - It accepts a file whose first line is a hymn header, and a file that ends without the double blank line.
  - It drops `R…` entries from `Related:`.
  - It accepts ` - ` as well as `–` as the separator in `Subject:` (Isaiah's file has one hyphen).
  - It trims `Meter:` and `Reference:`.
- **New Gradle task:** `:databaseProvisioner:runGerman`.
- **Provisioning must run from WSL with the Linux JDK:** `JAVA_HOME=/home/lemue/.jdk ./gradlew ...`. Through the Windows JVM it failed at random points with duplicate primary keys and once `SQLITE_CORRUPT`. The full write-up is in the hymn-provisioning skill.

## Before/after verification

- **Integrity and counts:** `PRAGMA integrity_check` returns `ok`. The DB still has 13,687 hymns and 69,627 stanzas, all 482 `G` hymns are present, and none are missing or extra. The round trip `exportSql` → `importSql` is clean.
- **Non-German hymns:** there are no real changes. 125 English parents' `related` lists were only reordered, because it's a `HashSet`.
- **German metadata:**
  - `related` is now `E<n>` (previously empty), matching the Spanish convention.
  - `tune` is now filled from the English parent, again matching Spanish.
  - G420's stray `R729` has been removed.
  - Two meters gained their final dot, and the leading space was removed from 37 `verse` values.
- **German lyrics:** only **G64** and **G269** changed (`Wir, in Seinem Leibe`, `Nein! worauf warten`). These are the only lines from Isaiah's file that weren't already in the app.

## Regressions caught and fixed: DB fixes missing from Isaiah's file

The first run showed that re-provisioning from Isaiah's file would **undo 5 older fixes** that were made directly in `hymns.sql` (commits `c2e4455d` 2020 and `712a39c6` 2023) and never sent back to his team:

| Hymn | Isaiah's file | DB (kept) |
|---|---|---|
| G8 | `seine Herrlichkeit zu leben!` | `Seine …` (divine pronoun) |
| G9 | `Lieht und Liebe` | `Licht und Liebe` |
| G9 | last stanza numbered `8` | `Chorus:` |
| G21 | `Eingel und Heilige` | `Engel und Heilige` |
| G112 | `Wir als Einer, niemand…` | `Wir stehn als Einer, niemand…` (the meter needs it) |
| G331 | `wohnt in ihn.` | `wohnt in ihr.` (refers to *die Gemeinde*) |

These were applied to our `New_German_hymns.txt` before the final run.

**Send back to Isaiah:** `docs/v5.5/Liederbuch_app_v5_merged_04.10.2026.txt` is his file with these 6 line fixes merged in. His team should base the renumbered revision on it, or these fixes will be lost again.
