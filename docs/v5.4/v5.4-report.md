## Related bug found while investigating the tune-code issue

`ProvisionSpanish2026.groovy` has a rule that parses a `"hymn code hymnalnet:"` line into the `tune` field (line ~174). `ProvisionGermanYouth.groovy` has **no equivalent rule** — so today, the `Hymn code Hymnalnet: 53432177615` line in G2163's entry doesn't get parsed into `tune` at all. It falls through to a generic catch-all branch in `createNewHymn()` and gets absorbed as bogus lyric text in a fake "chorus" stanza instead. Fixing G2163's tune code will require adding a matching parsing branch to `ProvisionGermanYouth.groovy`, not just updating the data value.
